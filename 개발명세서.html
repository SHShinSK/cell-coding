§ 0
개요 및 설계 철학
Overview & Design Philosophy

세포코딩(Cell Coding)은 생물학의 세포 이론에서 영감을 받은 새로운 프로그래밍 패러다임이다. 모든 프로그램의 구성 단위는 세포(cell)이며, 세포는 고유한 역할을 가지고, 막(membrane)을 통해 외부와 선택적으로 통신하며, 신호(signal)를 통해 유기적으로 연결된다.

세포코딩은 기존 언어(Python, TypeScript, Go 등) 위에서 동작하는 트랜스파일 방식의 DSL로 설계된다. 독립 언어로 시작하지 않고 기존 생태계를 흡수하며 점진적으로 도입 가능하다.

Why now: Classical software evolved around a narrower input-process-output frame. In Physical AI systems, both sensing and acting become multimodal and continuous, so a single linear pipeline model becomes insufficient.

왜 지금 필요한가: 고전 소프트웨어는 상대적으로 좁은 입력-처리-출력 프레임을 중심으로 발전했다. 그러나 Physical AI 시스템에서는 감지와 행동이 모두 다중 모달·연속 흐름으로 확장되므로, 단일 선형 파이프라인 모델만으로는 한계가 드러난다.

Functional cell definition: Cell Coding treats software as a collaboration network of functional cells. Each cell owns one role, is guarded by membrane contracts, and cooperates with others only through signals.

기능 세포 정의: Cell Coding은 소프트웨어를 기능 세포들의 협업 네트워크로 본다. 각 세포는 하나의 역할을 담당하고, 막 계약으로 경계를 유지하며, 다른 세포와는 신호를 통해서만 협업한다.

📐 핵심 철학 세포는 상태를 숨기는 것이 아니라 역할을 선언한다. 세포는 다른 세포를 호출하는 것이 아니라 신호에 반응한다. 세포는 단독으로 살아남을 수 있어야 하며, 집합적으로 유기체를 이룬다.

키워드 인덱스
Keyword Index

세포코딩의 모든 예약어(reserved keyword)는 생물학적 용어를 기반으로 한다. 총 24개의 키워드로 언어 전체를 구성한다.

cell
UNIT · 세포
모든 구성의 최소 단위. 단 하나의 역할을 가진다.
tissue
COMPOSITION · 조직
같은 목적을 가진 세포들의 선형/병렬 클러스터.
organ
COMPOSITION · 기관
여러 조직이 하나의 기능을 위해 협력하는 단위.
organism
COMPOSITION · 유기체
전체 시스템. 기관들의 최상위 컨테이너.
signal
COMMUNICATION · 신호
세포 간 유일한 통신 수단. 불변(immutable)이다.
membrane
INTERFACE · 막
세포의 입출력 계약. 수용·방출 신호를 정의한다.
genome
TEMPLATE · 유전자
재사용 가능한 세포 설계도. 제네릭 템플릿.
nervous
SYSTEM · 신경계
기관 간 신호를 중계하는 이벤트 버스.
immune
SYSTEM · 면역계
오류 세포를 격리하고 시스템을 보호한다.
on
HANDLER · 반응
특정 신호를 수신했을 때 실행할 로직 선언.
emit
ACTION · 방출
신호를 외부로 발송한다. 반환값이 아니다.
absorb
ACTION · 흡수
신호를 소비하여 더 이상 전파되지 않게 한다.
divide
OPERATION · 분열
세포를 동적으로 복제·병렬화한다.
mutate
OPERATION · 변이
세포의 역할이나 막을 런타임에 재정의한다.
apoptosis
LIFECYCLE · 세포사멸
세포의 자발적 종료 및 자원 해제.
role
METADATA · 역할
세포가 하는 일을 자연어로 선언하는 필수 속성.
§ 2
cell — 세포
The Fundamental Unit

cell은 세포코딩의 가장 작은 독립 단위다. 세포는 반드시 role을 가져야 하며, membrane을 통해 외부와 통신하고, on 핸들러로 신호에 반응한다. 세포는 다른 세포를 직접 참조하거나 호출할 수 없다.

📏 불변 규칙 ① 세포는 반드시 role 을 선언해야 한다. ② 세포는 membrane 에 선언되지 않은 신호를 emit할 수 없다. ③ 세포는 다른 세포를 import하거나 직접 호출할 수 없다.

해부 구조

cell-code anatomy.cell 
// ── 세포의 완전한 해부 구조 ──────────────────────────────

cell EmailValidator {

  // [필수] 역할 선언 — 자연어, 이 세포의 존재 이유
  role     : "이메일 주소의 형식과 도메인 유효성을 검사한다"

  // [선택] 세포 태그 — 검색·분류용 메타데이터
  tags     : ["validation", "auth", "input"]

  // [선택] 생존 범위 — 세포의 수명 정책
  lifespan : stateless   // stateless | persistent | session

  // [필수] 막 — 입출력 계약
  membrane {
    accepts: RawEmailInput
    emits  : ValidEmail | InvalidEmail
    rejects: NullInput    // 이 신호는 통과시키지 않는다
  }

  // [선택] 내부 상태 — lifespan이 persistent일 때만 유효
  nucleus {
    cache: Map<String, Bool>
  }

  // [필수] 신호 핸들러
  on (RawEmailInput input) {
    if isValidFormat(input.address) && domainExists(input.address) {
      emit ValidEmail(address: input.address)
    } else {
      emit InvalidEmail(reason: "형식 오류 또는 도메인 불일치")
    }
  }

  // [선택] 세포 사멸 훅
  apoptosis {
    clearCache(nucleus.cache)
  }
}

막 (Membrane)

막은 세포의 입출력 계약이다. 막에 선언된 신호만이 세포를 관통할 수 있다. 막은 세포의 공개 API이자 유일한 인터페이스다.

키워드의미예시
accepts이 신호가 올 때 세포가 활성화된다accepts: LoginRequest
emits세포가 처리 후 방출할 수 있는 신호emits: TokenIssued | AuthFailed
rejects이 신호는 명시적으로 차단한다rejects: GuestRequest
observes반응하지는 않지만 감지·로깅한다observes: AnySignal
passthrough신호를 변환 없이 그대로 전달한다passthrough: HealthCheck

§ 3
signal — 신호
The Communication Primitive

신호는 세포 간 유일한 통신 수단이다. 신호는 불변(immutable)이며, 생성 후 수정될 수 없다. 신호는 데이터를 운반하지만 행동을 명령하지 않는다. 어떤 세포가 신호를 받아 무엇을 할지는 전적으로 수신 세포의 책임이다.

💡 메시지 vs 신호 OOP의 메시지는 수신자를 알고 있다. 세포코딩의 신호는 수신자를 모른다. 신호는 공기 중에 방출되고, 관심 있는 세포들이 반응할 뿐이다. 이것이 결합도를 근본적으로 낮춘다.

신호 유형

cell-code signals.cell 
// ── 신호 정의 ────────────────────────────────────────────

// 1. 데이터 신호 (가장 일반적) — 불변 데이터 운반
signal UserRegistered {
  userId   : UUID
  email    : Email
  createdAt: Timestamp
}

// 2. 에러 신호 — immune 시스템이 감지
signal DatabaseError extends ErrorSignal {
  code     : Int
  message  : String
  retryable: Bool
}

// 3. 빈 신호 — 존재 자체가 의미
signal SessionExpired   // 데이터 없음, 발생 사실만 전달
signal HealthCheckPing  // 상태 확인 요청

// 4. 제네릭 신호 — genome과 함께 사용
signal Paginated<T> {
  items  : List<T>
  total  : Int
  page   : Int
  hasMore: Bool
}

// 5. 우선순위 신호 — nervous 시스템이 처리 순서 결정
signal PaymentFailed priority: critical {
  orderId : UUID
  amount  : Money
  reason  : String
}

신호 라우팅 규칙

규칙설명예외
broadcast-first신호는 기본적으로 모든 관심 세포에 전파된다absorb로 중단 가능
immutability신호는 전파 중 변경될 수 없다없음 (절대 불변)
no-reply신호는 응답을 기대하지 않는다query 패턴 예외
priority-ordercritical > high > normal > low 순으로 처리nervous 설정으로 오버라이드
type-safety막에 선언된 타입과 일치하지 않으면 전달되지 않는다AnySignal 와일드카드
cell-code signal-routing.cell 
// ── 신호 흐름 패턴 ───────────────────────────────────────

// 패턴 1: 파이프라인 (A → B → C)
cell Parser {
  membrane { accepts: RawInput; emits: ParsedData }
  on(RawInput raw) { emit ParsedData(parse(raw)) }
}

// 패턴 2: 분기 (one signal → many cells)
cell OrderCompleted_EmailNotifier {
  membrane { accepts: OrderCompleted; emits: EmailSent }
  on(OrderCompleted e) { emit EmailSent(to: e.userEmail) }
}

cell OrderCompleted_StockReducer {
  membrane { accepts: OrderCompleted; emits: StockUpdated }
  on(OrderCompleted e) { emit StockUpdated(sku: e.sku) }
}

// 패턴 3: 흡수 (신호 전파 중단)
cell RateLimiter {
  membrane { accepts: ApiRequest; emits: TooManyRequests }
  on(ApiRequest req) {
    if exceeded(req.clientId) {
      absorb   // 신호 전파 중단 — 다음 세포에 도달하지 않음
      emit TooManyRequests(clientId: req.clientId)
    }
  }
}

// 패턴 4: 질의 (query — 응답을 기다리는 특수 신호)
cell UserFinder {
  membrane {
    accepts: FindUser query       // query 키워드: 응답 신호 기다림
    emits  : UserFound | UserNotFound
  }
  on(FindUser q) {
    let user = db.find(q.userId)
    user ? emit UserFound(user) : emit UserNotFound
  }
}
§ 4
tissue — 조직
Ordered Cell Clusters

tissue는 같은 목적을 가진 세포들의 묶음이다. 조직 내 세포들은 선형(linear), 병렬(parallel), 또는 조건부(conditional) 흐름으로 연결된다. 조직은 그 자체가 하나의 막을 가져 외부에서는 단일 세포처럼 보인다.

cell-code auth-tissue.cell 
// ── 조직: 인증 파이프라인 ────────────────────────────────

tissue AuthPipeline {

  // 조직의 외부 계약
  membrane {
    accepts: LoginRequest
    emits  : SessionCreated | AuthDenied
  }

  // 선형 흐름: 순서대로 실행
  flow linear {
    InputSanitizer    // 1. 입력 정제
    → CredentialChecker // 2. 자격 확인
    → TokenIssuer       // 3. 토큰 발급
    → SessionCreator    // 4. 세션 생성
  }

  // 조건부 분기
  when (AuthDenied) {
    AuditLogger     // 실패시 감사 로그
    BruteForceGuard // 브루트포스 감지
  }
}

// ── 병렬 조직 ────────────────────────────────────────────
tissue OrderNotifications {

  membrane {
    accepts: OrderCompleted
    emits  : AllNotified
  }

  // 병렬 흐름: 동시 실행, 모두 완료 후 emit
  flow parallel {
    EmailNotifier
    SmsNotifier
    PushNotifier
    SlackNotifier
  }

  after all {
    emit AllNotified
  }
}
§ 5
organ — 기관
Functional System Unit

organ은 여러 조직이 협력하여 하나의 도메인 기능을 담당하는 단위다. 기관은 독립적인 신호 공간(signal namespace)을 가지며, 기관 내부의 신호는 기관 밖으로 자동 전파되지 않는다. 기관 간 통신은 nervous를 통해서만 가능하다.

cell-code user-organ.cell 
organ UserOrgan {

  // 기관의 외부 계약
  membrane {
    accepts: LoginRequest | RegisterRequest | ProfileUpdateRequest
    emits  : UserEvent    // 기관의 외부 신호 타입
  }

  // 내부 조직 구성
  tissues {
    AuthPipeline     // 인증 처리
    RegistrationFlow // 회원가입 처리
    ProfileManager   // 프로필 관리
  }

  // 기관이 외부에 공개하는 신호 (나머지는 격리)
  exports {
    UserRegistered
    UserLoggedIn
    UserDeleted
  }

  // 기관 수준 상태 (모든 조직이 공유)
  shared {
    userRepository: UserRepository
    auditLog       : AuditLogger
  }
}
§ 6
organism — 유기체
The Complete System

organism은 전체 시스템의 최상위 컨테이너다. 유기체는 기관들의 목록, 신경계(eventbus), 면역계(error handler), 그리고 환경(environment) 설정을 정의한다.

cell-code app.organism 
organism ECommerceApp {

  // ① 기관 목록
  organs {
    UserOrgan
    ProductOrgan
    OrderOrgan
    PaymentOrgan
    NotificationOrgan
  }

  // ② 신경계 — 기관 간 신호 라우팅
  nervous EventBus {
    // 어떤 신호가 어느 기관으로 흐르는지 명시
    UserOrgan.UserRegistered    → NotificationOrgan
    OrderOrgan.OrderPlaced       → [PaymentOrgan, ProductOrgan]
    PaymentOrgan.PaymentConfirmed → [OrderOrgan, NotificationOrgan]
    PaymentOrgan.PaymentFailed    → [OrderOrgan, NotificationOrgan]
  }

  // ③ 면역계 — 오류 처리 전략
  immune ErrorPolicy {
    on DatabaseError   → retry(3) then quarantine
    on NetworkTimeout  → retry(2) then fallback
    on UnknownError    → isolate & alert
    escalate           : CriticalAlertOrgan
  }

  // ④ 환경 설정
  environment {
    runtime  : "node:20"
    transport: "redis"    // nervous 의 실제 전송 계층
    scale    : auto        // 세포 자동 분열·스케일링
    observe  : "opentelemetry"
  }
}
§ 7
nervous — 신경계
Inter-organ Signal Bus

신경계는 기관 간 신호의 흐름을 관장한다. 신경계 없이 기관은 완전히 격리된 섬이다. 신경계가 배선(wiring)을 담당함으로써 기관 자체는 라우팅에 대해 전혀 알 필요가 없다.

cell-code nervous-system.cell 
nervous AppNervousSystem {

  // 기본 라우팅
  UserOrgan.UserBanned → OrderOrgan  // 단순 전달

  // 변환 라우팅 — 신호를 변환하여 전달
  PaymentOrgan.PaymentConfirmed
    → transform(p) { OrderApproved(orderId: p.orderId) }
    → OrderOrgan

  // 조건부 라우팅
  OrderOrgan.OrderPlaced
    → when (o.amount > 1000000) → FraudDetectionOrgan
    → always                    → PaymentOrgan

  // 신호 집계 — 여러 신호가 모두 도착해야 발화
  aggregate {
    wait: [PaymentConfirmed, InventoryReserved]
    emit: ReadyToShip
    timeout: 30s → FulfillmentFailed
  }
}
§ 8
immune — 면역계
System-wide Error Policy

면역계는 이상 세포(오류 발생 세포)를 감지하고, 격리하며, 시스템이 계속 생존할 수 있도록 보호한다. 각 기관이 자체 면역 정책을 가질 수 있고, organism 레벨에서 전역 정책을 정의한다.

cell-code immune.cell 
immune GlobalPolicy {

  // 오류 유형별 대응 전략
  on DatabaseError {
    strategy: retry(attempts: 3, backoff: exponential)
    fallback: useCache
    escalate: after 3 failures
  }

  on MemoryExceeded {
    strategy: quarantine   // 세포 격리, 신호 차단
    recover : divide        // 부하를 분산 세포로 분열
  }

  on UnhandledSignal {
    strategy: deadLetter   // 처리 불가 신호를 보관
    alert   : true
  }

  // 회로 차단기 (Circuit Breaker)
  circuit {
    threshold  : 5 failures in 60s
    open       : 30s   // 차단 시간
    halfOpen   : 1 probe  // 회복 탐침
  }
}
§ 9
genome — 유전자
Cell Templates & Generics

genome은 재사용 가능한 세포 설계도다. 타입 파라미터를 받아 구체화되며, OOP의 제네릭 클래스나 Rust의 트레이트와 유사하지만 역할 중심으로 설계된다.

cell-code genome.cell 
// ── Genome: 재사용 가능한 세포 템플릿 ───────────────────

genome CrudCell<Entity, CreateCmd, UpdateCmd> {
  membrane {
    accepts: CreateCmd | UpdateCmd | DeleteCmd<Entity>
    emits  : Created<Entity> | Updated<Entity> | Deleted<Entity>
  }

  on(CreateCmd cmd) { emit Created<Entity>(persist(cmd)) }
  on(UpdateCmd cmd) { emit Updated<Entity>(merge(cmd)) }
  on(DeleteCmd<Entity> cmd) { emit Deleted<Entity>(cmd.id) }
}

// genome 인스턴스화 — 구체 세포 생성
cell ProductCell from CrudCell<Product, CreateProduct, UpdateProduct>
cell UserCell    from CrudCell<User,    CreateUser,    UpdateUser>

// ── 행동 Genome (인터페이스처럼 사용) ─────────────────
genome Retryable {
  maxRetries: Int = 3
  backoff   : BackoffStrategy = exponential

  on ErrorSignal {
    if retries < maxRetries { retry }
    else { emit Exhausted }
  }
}

// 세포에 genome 믹스인
cell PaymentProcessor with Retryable {
  role: "결제 처리 및 자동 재시도"
  membrane {
    accepts: ProcessPayment
    emits  : PaymentSuccess | PaymentFailed
  }
  // Retryable의 재시도 로직이 자동 주입됨
}
§ 10
변이 및 분화
Mutation & Differentiation

세포는 런타임에 분열(divide)하거나 변이(mutate)할 수 있다. 이는 스케일링, A/B 테스트, 롤링 배포, 기능 플래그를 언어 수준에서 지원하는 메커니즘이다.

cell-code mutation.cell 
// ── 세포 분열 — 수평 스케일링 ───────────────────────────
cell ImageProcessor {
  role: "이미지 리사이징 및 압축"
  lifespan: stateless

  // 부하에 따라 자동으로 세포 분열
  divide when (queue.depth > 100) {
    max     : 16         // 최대 16개 복제
    strategy: round-robin
  }

  membrane { accepts: ImageTask; emits: ImageReady }
  on(ImageTask t) { emit ImageReady(process(t)) }
}

// ── 세포 변이 — A/B 테스트 / 기능 플래그 ────────────────
cell RecommendationEngine {
  role: "상품 추천 알고리즘"

  // 환경 변수에 따라 알고리즘 변이
  mutate when (env.feature.mlRecommend == true) {
    role: "ML 기반 개인화 추천"
    membrane { accepts: UserContext; emits: MLRecommendations }
    on(UserContext u) { emit MLRecommendations(mlModel.predict(u)) }
  }

  // 기본 동작 (변이 조건 미충족 시)
  membrane { accepts: UserContext; emits: BasicRecommendations }
  on(UserContext u) { emit BasicRecommendations(rule.apply(u)) }
}
§ 11
타입 시스템
Type System

세포코딩의 타입 시스템은 신호 중심으로 설계된다. 신호 타입의 호환성이 막의 연결 가능성을 결정한다. 타입 추론을 지원하지만 막 선언은 명시적 타입이 필수다.

기본 타입

Int Float String Bool UUID Timestamp Money Email URL List<T> Map<K,V> Option<T> Result<T,E> AnySignal ErrorSignal NullSignal

타입 호환성 규칙

규칙설명
structural이름이 아닌 구조로 호환성 판단 (구조적 서브타이핑)
signal unionA | B는 A 또는 B 신호를 수용한다는 의미
signal extends하위 신호 타입은 상위 타입을 수용하는 막에도 전달된다
AnySignal모든 신호를 수용 (observes와 함께 사용, accepts에는 지양)
NullSignal신호 없음. reject나 조건부 emit 불발 시 사용

from cellcoding import cell, membrane, signal, emit

# 기존 Python 함수를 세포로 래핑
@cell(
    role="사용자 이메일 검증",
    accepts="RawEmailInput",
    emits=["ValidEmail", "InvalidEmail"]
)
def email_validator(input_signal):
    if is_valid_email(input_signal.address):
        return emit("ValidEmail", address=input_signal.address)
    return emit("InvalidEmail", reason="형식 오류")
